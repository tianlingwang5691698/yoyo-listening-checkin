# 语法课堂规则

## 定位

- 用例句讲清语法本质，不照搬教材长篇讲义。
- 学习路径按知识类型选择：观察例句 → 必要分析 → 本质规则 → 小练习。
- 每节控制一个核心问题，内容通俗但术语必须准确。

## 目录

- 语法页顶部顺序：考点分类 → 练习记录 → 语法课堂。
- 词法按十大词性组织：名词、代词、数词、冠词、动词、形容词、副词、介词、连词、感叹词。
- 动词路径：动词地图 → 具体课程地图 → 单节学习卡。
- 动词地图按作用、是否带宾语、句中任务、形式变化分类。

## 单节内容

- 每节至少 3 个不同类别例句、3 道对应练习，这只是最低保障，不是固定上限或统一模板。
- 讲解中的每一条原子规则都必须至少有 1 个直接对应例句和 1 道直接对应练习；规则有多个并列用法时，必须拆分或按用法数量追加例句与练习。
- 课程数据必须记录 `ruleCoverage`，逐条指向真实对应的 `exampleIndexes` 和 `questionIndexes`；禁止为了通过测试填写与语义不对应的索引。
- 练习按实际题数逐题推进，每节不得少于 3 题；答对当前题后才能继续。
- 当前小节全部题目完成后进入下一小节；最后一节显示“完成并返回”。
- 完整专题必须区分“核心必学 / 进阶挑战”；核心放所有学生必须掌握的概念、规则和高频使用语境，进阶放低频特殊情况、复杂结构和综合辨析。
- 核心与进阶不设固定节数，必须按知识必要性判断，禁止为了统一数量把必会内容放入进阶。
- 分层判断顺序：是否影响基础理解 → 是否高频使用 → 是否为后续知识前提 → 是否主要属于特殊或综合情形。
- 每个已开放专题的每节课程必须同时具备规则、例句、必要的成分分析、自适应说明和对应练习。
- 底部固定提供“返回 / 继续”：返回上一层课程地图，继续进入下一题或下一节。

## 成分分析

- 完整例句必须做可视化成分拆解，不能只显示纯文字。
- 标准术语：主语、谓语动词、宾语、定语、状语、助动词、情态动词、连词等。
- 定语和状语必须细分，不使用“补充成分”等模糊名称。
- 介词短语修饰名词时标为“介词短语作后置定语”。
- 状语按语义标为时间、地点、方式、频率、原因、目的、条件等。
- 并列句分别拆出连词和各分句成分。

## 颜色语义

- 主语：蓝色。
- 谓语：珊瑚色。
- 宾语：绿色。
- 定语：紫色。
- 状语：蓝紫色。
- 助动词、情态动词：金色。
- 连词：玫红色。
- 颜色、底线和文字标签必须同时存在，不能只依赖颜色表达。

## 自适应讲解

- 不强制每个例句显示翻译，只在中英文语序或表达方式有明显差异时讲翻译。
- 后置定语必须讲“英语后置、中文通常前移”。
- 时间、地点、方式、频率状语仅在位置与中文不同或容易误解时讲翻译顺序。
- 拼写课重点展示拼写观察和变形规则，不显示无意义的逐词翻译。
- 发音课重点展示音标、发音条件和音节变化，不显示“中文翻译 / 翻译顺序”。
- 疑问、否定、助动词等内容重点展示结构转换；只有中文表达方式明显不同时才补翻译。
- 普通主谓宾顺序与中文一致时，保留成分分析即可，避免重复信息。
- 构词法课程以“结构观察、拼写观察、发音观察”为主，不机械显示中文翻译；必须区分派生构词与复数、时态、比较级等屈折变化。
- 词缀只用于提示词义方向和词性，不得把所有单词强行拆解；不透明词形必须明确要求结合语境和词典校验。

## UI 与主题

- 语法课堂首页按“词法、句法、从句与复合句、表达与标点”组织；词法下一层先分“十大词性、构词法”，十大词性不得直接占据课堂首页。
- 专题内部按知识所属关系分类，核心/进阶只表示学习难度，不得替代知识分类。
- 每个词性及构词法专题都必须先显示独立类别地图，再进入该类别的课程地图；即使课时较少也不得直接平铺全部小节。
- 每节课必须且只能属于一个类别；类别展开后课程 ID 必须完整覆盖、无重复、无未知项，类别说明和节数必须与内容一致。
- 显示层级固定为语法体系 → 分类地图 → 专题目录 → 课程地图 → 单节学习卡，每屏只承担一个主要任务。
- 每一层必须同时提供可读文字的“返回上一层”操作；顶部返回键按当前层级返回，禁止从深层页面直接退出整个课堂。
- 第三人称单数等单一微观规则必须放入所属课程小节，不得与“完整动词课程”等上位专题并列成独立入口；确有专项练习需求时也只能作为课程内部章节。
- 雾蓝主题使用轻玻璃卡、柔和结构色和深蓝主动作。
- 图书馆主题使用纸张、黄铜编号、深墨主动作和低圆角。
- 两套主题共用内容和交互状态，但各自保持材质与按钮语言。
- 中英文都要自然换行，禁止拆英文单词。

## 课程设计硬规则

- 新专题必须先列完整知识边界，再按“基础理解、高频使用、后续前提、特殊综合”分核心与进阶，不凑固定节数。
- 每节只解决一个核心问题；例句类别必须覆盖该规则的主要变体，练习与例句类别一一对应。
- 翻译、成分分析、拼写规则、发音规则和结构转换按知识类型自适应出现，禁止每节机械套同一模板。
- 发布前必须完成中英文内容对等审查：目录、规则、例句标签、翻译提示、题干、选项、反馈和按钮均不得缺失。

## 性能硬规则

- 语法入口首屏只保留目录和摘要；不得在主页顶层引入或首屏 `setData` 完整课程。词法大数据必须放入 `requiredComponents` 懒加载组件，用户点击对应专题后才实例化。
- 课程运行时文件必须放在小程序可打包目录；`project.config.json.packOptions.ignore` 中的 `data/`、`docs/`、`tests/` 只能存放非运行时资料。
- 可读课程源文件保存在 `data/grammar-classroom/course-sources/`，小程序实际加载由 `scripts/build_grammar_classroom_runtime.sh` 生成的 `grammar-package/domain/grammar-classroom/` 压缩文件；提交前必须比对两者业务教学字段一致，运行时可剥离仅供测试的 `ruleCoverage` 元数据。
- 语法主包页只保留“语法课堂”路由入口；完整课程页、懒加载组件和课程运行时数据统一放在 `grammar-package/` 普通分包，后续词法、句法、从句等不得再占用主包空间。
- 语法页可读脚本保存在 `data/grammar-classroom/page-source/index.js`，`pages/grammar/index.js` 也由同一脚本生成压缩运行版；语法逻辑只修改可读源文件，禁止直接手改生成文件。
- 完整专题必须在用户点击后加载；课程模块只能在 `requiredComponents` 组件顶层使用固定字面路径 `require('fixed/path')`，禁止在语法主页顶层引入，也禁止拼接路径的动态 `require`。
- 大型独立专题必须使用独立懒加载组件，不得让其他入口连带解析无关课程模块；能归入上位课程的小规则不得为迁就加载结构单独设入口。
- 课程页只向视图层注入当前专题；进入单节后优先保证首个题可作答，不预构建其他词性课程。
- 类别地图和课程地图只向视图层注入标题、摘要、难度等小型元数据；规则、例句和练习保留在页面内存，进入单节时才注入。
- `pageReady` 以目录或第一个可点小节真实渲染为准；本地课程目标 `<200ms`，硬上限 `<800ms`。
- 不使用全页 `showLoading`、等待文案或空白中转页；失败必须保留可返回页面。

## 测试与埋点硬规则

- 入口页和课程页必须分别上报 `pageReady`；打开小节上报 `actionMs`，后续接入云端时再独立上报 `cloudRefresh`和 `dataFresh`。
- 每个已开放专题必须自动检查：核心/进阶分组、每条规则都有直接例句与对应练习且映射索引有效、答案有效、中英文可构建、两套主题样式存在。例句与练习数量由规则变体决定，不设固定 3 个。
- “完整课程”还必须用专题知识边界 ID 做回归检查，禁止仅以总节数或总题数判断完整性；分组展开后必须与课程 ID 同序、无重复、无遗漏。
- 所有专题必须自动校验类别元数据完整，类别 lessonIds 对课程 ID 恰好覆盖一次；长、中、短课程还必须回归对应的分层展示策略与逐层返回。
- 构词法测试必须覆盖基词/词根/词缀、派生与屈折、常用前后缀、转化、合成、词性槽位、拼写与重音变化、多层构词和生词推断边界。
- 介词测试必须覆盖形式与宾语、时间、空间位置与运动、方式与逻辑关系、句法功能、固定搭配，以及介词/连词/小品词辨析；不得只用 at/on/in 代表完整介词课程。
- 必须有首屏回归测试：入口 `classroom` 不含完整课程数组，序列化数据大小不得随新课程线性增长。
- 每次变更必须通过 `node --check`、语法课堂回归测试、`git diff --check` 和微信开发者工具编译。
- 测试期失败信息必须显示到页面 debug 区，格式为 `DEBUG: page/function -> builder/store -> field`；验收后撤除临时 debug 和 console。

## UI 验收硬规则

- 验收尺寸至少覆盖 iPhone 12/13 等效宽度和一个小屏宽度；中英文分别检查无横向溢出、无单词拆分、按钮文字居中。
- 雾蓝玻璃与静谧图书馆必须各自验收目录、课程地图、例句分析、正误反馈和底部操作，不得只验收换色。
- 成分色必须同时有文字标签和底线；正确/错误必须有高对比色块与文字，不能只靠颜色区分。
- 底部始终是“返回 / 继续”双操作；未答对时继续按钮显式禁用，最后一题改为“完成并返回”。
- 发布前按 `docs/UI_CHANGE_CHECKLIST.md` 逐项验收，并将实际改动追加到 `docs/UI_DESIGN_LANGUAGE_LOG.md`。

## 数据与记录

- Demo 内容不得覆盖现有真题题库或改变考点练习结构。
- 未明确接入学习进度前，语法课堂只操作当前内存状态，不写学生完成记录。
- 后续接入云端时必须增量增加课程数据，保持旧版本和线上用户兼容。
