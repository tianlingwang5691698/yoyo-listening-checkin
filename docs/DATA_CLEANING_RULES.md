# 本地数据清洗规则

适用：阅读、听力、语法、写作、口语题目、词汇、transcript 和所有题库结构化任务。

## 当前基线（2026-07-23）

- 本文件是跨模块总规则；上海初中真题、高中真题、音频和口语还必须分别读取对应专项规则。
- 当前正式结构以“说明、标题/副标题、正文段落、题组、题目、选项、答案”分字段保存为准，禁止为了显示方便重新压成一个字符串。
- 阅读现行分段门禁覆盖初中 753 篇、高中 181 篇、IELTS 144 篇；高中 Summary Writing 覆盖 18 题、14 个独立标题、4 篇无标题原文和 77 个真实正文段落。
- 学生手工标记是练习记录，不是题库内容：只在提交/完成时保存最终状态，沿用现有记录，不新建集合；家长只读查看，不写学生进度。
- 口语数据、录音、评分、身份分流和 240 秒模型超时统一遵循 `docs/SPEAKING_PRACTICE_RULES.md`。

## 总规则

- 语法、阅读、写作、听力、口语的清洗脚本、结构恢复、展示兼容或准入门禁每次变化，都必须在同一次提交中更新本文件和对应专项规则，并同步增加/修改自动回归；不得只改代码或只改文档。
- IELTS 写作评分返回结构、字段兼容、评分降级和失败诊断还必须遵循 `docs/WRITING_SCORING_RULES.md`。
- 处理词汇、词书、音标、释义、例句和例句翻译时，还必须遵循 `docs/VOCABULARY_DATA_RULES.md`。
- 清洗前先读已有正式 JSON、清洗脚本和对应模块文档。
- 清洗前必须先拉云存储正式 JSON，确认线上字段、结构、展示样式和已有清洗口径；没有同类线上参考时，再借鉴相邻模块或同类年份规则。
- 原卷取证优先级固定为：同源原卷 Word/docx → 同源可保序文本 → 原 PDF 版面 → OCR。双栏、跨页、文本框和页眉页脚必须回看原图，不以单次抽取结果猜段落。
- 本地清洗结果只能作为候选，不直接覆盖线上正式数据。
- 最终上传的数据结构、路径和字段必须与线上存储现状保持兼容。
- 上传内容不能要求修改云函数或前端才能可用。
- 上传内容不能影响线上上一个版本用户继续使用原有内容。
- `_id` 必须稳定、可追溯、不可随机生成。
- 已上线 `_id`、题目、答案、音频路径、图片路径默认冻结。
- 缺关键字段的内容先进入 rejected/clean-report，不进入正式库。
- 不人工补写原文、题目、答案、解析；不跨年、跨区县、跨模块借内容。
- 新增内容必须保留来源字段或清洗报告，方便回查。
- 清洗报告至少记录：来源文件及哈希、受影响 `_id`、旧/新内容哈希、标题数、段落数、剔除污染类型、拒收原因和云端清洗前快照哈希。
- 生成脚本必须同步修正；禁止只手改最终 JSON，导致下次重建重新产生同一污染。
- 已上线旧数据需要展示层兼容时，兼容逻辑必须按稳定 `_id` 和来源结构确定性恢复，并用云端旧快照逐条回归；不能靠模糊猜测改变原文。

## 阅读

- A/B/C/D 分篇入库，不合并成一篇。
- passage 不完整、题数不足、选项缺失、答案不稳的不入正式库。
- 不把中文解析、考点说明、`故选` 写进题干、选项或正文。
- 逐题解析、答案句、翻译由学习包生成，不在清洗时硬写。
- 文章标题、副标题、题型说明和正文必须分开；`answer（根据短文/文章/对话内容……）` 等 OCR 题型说明不得成为第 1 段。
- 正文保留原卷自然段。线上旧正文空行被压平时，必须使用原卷段落起点元数据确定性恢复；没有原始换段证据时只能按完整句群分段，不能截断句子。
- IELTS 原文已有 A/B/C 等段标时保留原字母，不再叠加 `Paragraph A`；无字母时才使用数字段号。标题下的斜体副标题不计入 Paragraph 1。
- 段标是段落元数据，不得拼进正文句子，也不得占用正文的固定左栏宽度。
- 阅读标记统一为：点单词黄色、连续相邻单词蓝色短语、长按当前句绿色；不震动、不改变题库正文、不参与评分。
- 学生提交时才把最终标记与本次阅读记录一起保存；学生和家长回看同一记录，家长只读。

## 听力

- 所有音频转码、分片、上传和性能验收必须遵循 `docs/AUDIO_UPLOAD_STANDARD.md`。
- 一模、二模分目录、分 JSON，不能互相借题、借图、借音频。
- 正式练习必须同时有音频、原卷题目、答案、A 部分图片。
- A/B/C/D 段落结构必须保留。
- 图片只取听力题相关图片，不收 logo、二维码、阅读图片。
- transcript 只收真实听力原文；没有真实原文就标记缺失。
- 音频文件名新增时必须带内容指纹，避免缓存播放旧文件。
- Section、Questions 范围、题组标题、作答说明和表格/笔记静态字段各自独立保存；公共标题只在题组首次出现，不复制进每道题干。
- 听力题干可使用与阅读相同的轻量标记；练习中只保存在页面，提交答案时把最终标记与题目结果一起写入既有 `studyCompletedItems`，家长预览不写。

## 音频句级 transcript bundle

- 句级 bundle 的时间轴必须来自 ASR/WhisperX/Whisper `word_timestamps` 等真实音频时间；禁止按句子长度、字符数或平均比例硬摊整段音频。
- 官方文本优先作为 transcript 正文，ASR 只用于时间轴和漏句核对；若音频存在官方文本缺句，必须在清洗报告或 `scriptPatches` 中记录来源。
- 每条音频必须抽查首句、末句和至少 1 个中间段：文本内容要与当前音频一致，首句时间不能落在 `Track 1.1` 等报幕标签上。
- 生成后必须检查：每条 ASR 有 word/segment 时间、`startMs/endMs` 单调不重叠、最后一句 `endMs == durationMs`、轨道顺序和音频文件一一对应。
- 已上线 bundle 修正时走新增路径或兼容路径，不直接覆盖旧线上可用 bundle，除非明确确认不会影响线上用户。

## 语法

- 题目必须有年份、区县、模考类型和来源。
- 选择题必须有 A-D 选项和答案。
- `prompt` 只保留题干，不能残留 `A) ... B) ... C) ... D) ...`、`A. ...`、`A、...` 等选项文本；选项只能出现在 `options` 字段。
- 清洗后必须检查题干选项重复，尤其覆盖 `A)works`、`A) works`、`A. works`、`A、works` 等无空格/有空格格式。
- 分类只能使用固定 topic，不自创分类。
- 细分 topic 文件必须拆分，避免单接口超过 1MB。
- 题型说明、语篇正文、空格题和独立选择题不得互相粘连；当年无独立选择题时不能为了填目录而补造。
- 当前正式分类审核模型为 `gpt-5.6-sol`；模型只确认唯一主考点和依据，不改写题干、选项或答案。
- 语法题干标记与阅读相同，答完当前练习才保存最终标记，沿用现有完成记录，不新建集合、不参与正误判定。

## 写作

- 只保留作文题干、情景、字数要求和注意事项。
- 剔除范文、参考答案、评分标准、解析和听力文本。
- 一模、二模分 JSON，不混入同一入口。
- 高考卷含翻译题时，翻译与作文必须建为同一年卷下的独立任务，按原卷 `Translation → Guided Writing` 排序；每句翻译独立建模，保留题号、中文原文、括号提示词和可追溯参考译文，不得拼成一段。
- 初中写作必须拆为 `directions / scenario / requirements[] / notices[]`；参考问题按编号或问号分项，原卷表格使用 `promptTable`，不得把 OCR 答题线、试卷来源、阅读选词或答案串混入题纸。
- 高中 Summary Writing 固定使用 `articleTitle` 和 `articleParagraphs[]`：原卷有标题才填写标题，无标题保持空字符串；`scenario` 等于正文段落以空行连接，标题不得重复进入正文。
- Summary Writing 显示顺序固定为 `Directions → 写作任务 → 标题 → 正文`；Directions、标题和正文必须分字段保存，标题不得参与单词、短语或句子标记。
- Summary Writing 的来源 URL、页码、题号、分值和答题横线全部剔除；标题不参与单词、短语或句子标记，正文长按只覆盖当前真实句子。
- 写作题纸标记在提交作文/翻译时才保存最终状态，沿用 `writingAttempts`；家长只读预览，不写学生数据。
- IELTS 四项 Band 分完整有效时必须保留本次评分；逐项证据或升档讲解缺失只能标记为部分反馈，不得将整次有效评分改判为失败。
- 模型评分字段兼容必须覆盖 camelCase、snake_case、官方英文维度名和数组式 criterion 明细；只有四项 Band 分无法恢复时才允许重试或报错。
- IELTS Task 1 评分必须以原图为最终事实来源，先生成事实核对清单再评分；不得因为 `visualData` 缺少完整数值而跳过原图，也不得把次要中间值遗漏等同于重大特征遗漏。
- 同一评分版本、题目修订和作文正文必须生成稳定指纹；学生同题同文复用已有评分，家长预览缓存不得写入学生记录。

## 雅思真题

- 听力保留 Test、Section、Questions 范围、题组标题、作答说明、表格或表单静态字段、真实音频和 transcript；公共标题只在题组首次展示，不重复写入每道题。
- 阅读按原卷 Passage 和题组顺序清洗；Questions 范围、题组标题、作答说明只展示一次，笔记小标题仅在内容切换时出现，不重复粘到后续题干。
- 写作 Task 1 保留结构化题干、字数要求和原图表；图表优先从原 PDF 高分辨率裁剪，不人工重绘、不改变标签、比例或布局，并提供点击放大。Task 2 保留完整题干和字数要求。
- 口语按 Test、Part、题目原顺序入库，不把评分说明、示范答案或答案页内容混入题目。
- 雅思口语结构固定为：Part 1 保留 topic 和逐题 questions；Part 2 拆为 task、`You should say` cue points、closing prompt；Part 3 按 discussion topic 分组逐题保存。
- 旧 exercise 粘连多道口语题时，不改旧 ID 和旧 prompt；新结构可让多道 question 复用同一 exerciseId，并以原卷图片核对拆分结果。
- 原卷图片只作复核入口，结构化题目必须可直接阅读和练习，不得让图片成为唯一题目载体。
- IELTS 口语练习页不依赖“查看原题图片”；新结构化数据必须直接完成 Part 1–3 练习，历史图片路径只为旧版本兼容保留。
- 初中、高中、雅思作为同级入口时必须一次完整可见，不得依赖横向滑动才能发现雅思；级别顺序固定为 `初中 → 高中 → 雅思`。
- 缺失音频、正文、图表或答案时只拒收对应缺失部分，不借用其他 Test、版本或答案页补造。

## 口语题目

- 具体结构、音频、评分、记录和身份规则以 `docs/SPEAKING_PRACTICE_RULES.md` 为准。
- 题目必须短、明确、适合学生直接开口回答。
- 必须保留 prompt、参考目标、题型、来源和难度。
- 不把评分标准、模型反馈、参考范文混入题目正文。
- 已上线题目不改 `_id` 和 prompt；新增题目另建新 `_id`。

## 验证

- JSON 必须可解析。
- 选择题题干不得重复展示选项；语法题上传前必须抽查页面展示或用脚本统计 `badPrompt=0`。
- 正式库数量不得因本次清洗下降。
- rejected/clean-report 必须说明剔除原因。
- 上传前按 `docs/CLOUDBASE_SETUP.md` 的增量上传铁律合并。
- 全量门禁至少检查：重复 `_id=0`、结构字段缺失 `=0`、正文污染 `=0`、题干选项重复 `=0`、标题进入正文 `=0`、空段落/空锚点 `=0`。
- 旧云端兼容必须用正式云端旧详情逐条回归，验证恢复后的标题数、段落数、正文归一化内容和污染数与本地正式数据一致。
- 小程序运行时结构恢复元数据必须生成到未被 `project.config.json` 排除的 JS 模块；禁止从运行时代码直接 `require` 被排除的 `data/` 文件或 JSON 文件。

## 双栏 PDF / 答案听力文本

- 双栏 PDF 不直接用 `pdftotext` 结果入库；必须优先找同源 Word/docx 或可保序文本。
- 若只能用 PDF，必须抽查栏序：不能把右栏续段提前混入左栏正文。
- 纯页眉、页脚、版权、页码、音轨标记（如 `1.1`、`MID 1`、`END 1`）不得进入 transcript。
- 答案区、Model Language、Speaking Test 说明不得混入听力正文。
- Mid-level 多段音频按正文分界拆分，放在 U4 和 U5 之间；End-of-level 放在最后。
- ASR 只作时间轴/核对参考；正式 transcript 文本优先使用官方听力文本。
- 清洗后必须检查：`trackCount`、`lineCount`、空文本、异常音轨号、时间轴单调、最后一句 `endMs == durationMs`。
