# 本地数据清洗规则

适用：阅读、听力、语法、写作、口语题目、词汇、transcript 和所有题库结构化任务。

## 总规则

- 处理词汇、词书、音标、释义、例句和例句翻译时，还必须遵循 `docs/VOCABULARY_DATA_RULES.md`。
- 清洗前先读已有正式 JSON、清洗脚本和对应模块文档。
- 清洗前必须先拉云存储正式 JSON，确认线上字段、结构、展示样式和已有清洗口径；没有同类线上参考时，再借鉴相邻模块或同类年份规则。
- 本地清洗结果只能作为候选，不直接覆盖线上正式数据。
- 最终上传的数据结构、路径和字段必须与线上存储现状保持兼容。
- 上传内容不能要求修改云函数或前端才能可用。
- 上传内容不能影响线上上一个版本用户继续使用原有内容。
- `_id` 必须稳定、可追溯、不可随机生成。
- 已上线 `_id`、题目、答案、音频路径、图片路径默认冻结。
- 缺关键字段的内容先进入 rejected/clean-report，不进入正式库。
- 不人工补写原文、题目、答案、解析；不跨年、跨区县、跨模块借内容。
- 新增内容必须保留来源字段或清洗报告，方便回查。

## 阅读

- A/B/C/D 分篇入库，不合并成一篇。
- passage 不完整、题数不足、选项缺失、答案不稳的不入正式库。
- 不把中文解析、考点说明、`故选` 写进题干、选项或正文。
- 逐题解析、答案句、翻译由学习包生成，不在清洗时硬写。

## 听力

- 所有音频转码、分片、上传和性能验收必须遵循 `docs/AUDIO_UPLOAD_STANDARD.md`。
- 一模、二模分目录、分 JSON，不能互相借题、借图、借音频。
- 正式练习必须同时有音频、原卷题目、答案、A 部分图片。
- A/B/C/D 段落结构必须保留。
- 图片只取听力题相关图片，不收 logo、二维码、阅读图片。
- transcript 只收真实听力原文；没有真实原文就标记缺失。
- 音频文件名新增时必须带内容指纹，避免缓存播放旧文件。

## 音频句级 transcript bundle

- 句级 bundle 的时间轴必须来自 ASR/WhisperX/Whisper `word_timestamps` 等真实音频时间；禁止按句子长度、字符数或平均比例硬摊整段音频。
- 官方文本优先作为 transcript 正文，ASR 只用于时间轴和漏句核对；若音频存在官方文本缺句，必须在清洗报告或 `scriptPatches` 中记录来源。
- 每条音频必须抽查首句、末句和至少 1 个中间段：文本内容要与当前音频一致，首句时间不能落在 `Track 1.1` 等报幕标签上。
- 生成后必须检查：每条 ASR 有 word/segment 时间、`startMs/endMs` 单调不重叠、最后一句 `endMs == durationMs`、轨道顺序和音频文件一一对应。
- 已上线 bundle 修正时走新增路径或兼容路径，不直接覆盖旧线上可用 bundle，除非明确确认不会影响线上用户。

## 语法

- 题目必须有年份、区县、模考类型和来源。
- 选择题必须有 A-D 选项和答案。
- `prompt` 只保留题干，不能残留 `A) ... B) ... C) ... D) ...`、`A. ...`、`A、...` 等选项文本；选项只能出现在 `options` 字段。
- 清洗后必须检查题干选项重复，尤其覆盖 `A)works`、`A) works`、`A. works`、`A、works` 等无空格/有空格格式。
- 分类只能使用固定 topic，不自创分类。
- 细分 topic 文件必须拆分，避免单接口超过 1MB。

## 写作

- 只保留作文题干、情景、字数要求和注意事项。
- 剔除范文、参考答案、评分标准、解析和听力文本。
- 一模、二模分 JSON，不混入同一入口。
- 高考卷含翻译题时，翻译与作文必须建为同一年卷下的独立任务，按原卷 `Translation → Guided Writing` 排序；每句翻译独立建模，保留题号、中文原文、括号提示词和可追溯参考译文，不得拼成一段。

## 雅思真题

- 听力保留 Test、Section、Questions 范围、题组标题、作答说明、表格或表单静态字段、真实音频和 transcript；公共标题只在题组首次展示，不重复写入每道题。
- 阅读按原卷 Passage 和题组顺序清洗；Questions 范围、题组标题、作答说明只展示一次，笔记小标题仅在内容切换时出现，不重复粘到后续题干。
- 写作 Task 1 保留结构化题干、字数要求和原图表；图表优先从原 PDF 高分辨率裁剪，不人工重绘、不改变标签、比例或布局，并提供点击放大。Task 2 保留完整题干和字数要求。
- 口语按 Test、Part、题目原顺序入库，不把评分说明、示范答案或答案页内容混入题目。
- 雅思口语结构固定为：Part 1 保留 topic 和逐题 questions；Part 2 拆为 task、`You should say` cue points、closing prompt；Part 3 按 discussion topic 分组逐题保存。
- 旧 exercise 粘连多道口语题时，不改旧 ID 和旧 prompt；新结构可让多道 question 复用同一 exerciseId，并以原卷图片核对拆分结果。
- 原卷图片只作复核入口，结构化题目必须可直接阅读和练习，不得让图片成为唯一题目载体。
- 初中、高中、雅思作为同级入口时必须一次完整可见，不得依赖横向滑动才能发现雅思；级别顺序固定为 `初中 → 高中 → 雅思`。
- 缺失音频、正文、图表或答案时只拒收对应缺失部分，不借用其他 Test、版本或答案页补造。

## 口语题目

- 题目必须短、明确、适合学生直接开口回答。
- 必须保留 prompt、参考目标、题型、来源和难度。
- 不把评分标准、模型反馈、参考范文混入题目正文。
- 已上线题目不改 `_id` 和 prompt；新增题目另建新 `_id`。

## 验证

- JSON 必须可解析。
- 选择题题干不得重复展示选项；语法题上传前必须抽查页面展示或用脚本统计 `badPrompt=0`。
- 正式库数量不得因本次清洗下降。
- rejected/clean-report 必须说明剔除原因。
- 上传前按 `docs/CLOUDBASE_SETUP.md` 的增量上传铁律合并。

## 双栏 PDF / 答案听力文本

- 双栏 PDF 不直接用 `pdftotext` 结果入库；必须优先找同源 Word/docx 或可保序文本。
- 若只能用 PDF，必须抽查栏序：不能把右栏续段提前混入左栏正文。
- 纯页眉、页脚、版权、页码、音轨标记（如 `1.1`、`MID 1`、`END 1`）不得进入 transcript。
- 答案区、Model Language、Speaking Test 说明不得混入听力正文。
- Mid-level 多段音频按正文分界拆分，放在 U4 和 U5 之间；End-of-level 放在最后。
- ASR 只作时间轴/核对参考；正式 transcript 文本优先使用官方听力文本。
- 清洗后必须检查：`trackCount`、`lineCount`、空文本、异常音轨号、时间轴单调、最后一句 `endMs == durationMs`。
