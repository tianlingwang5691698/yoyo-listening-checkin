# 图书馆静谧 · 写作模块逐页设计规范

## 设计边界

- 主题：`themeId=library`，显示名“图书馆静谧”；`warm / 雾蓝玻璃` 继续为默认主题。
- 页面：`pages/material/index?module=writing`、`pages/writing/detail/index?id={{promptId}}`。
- 复用真实业务：`writingEm1 / writingEm2`、学段/模考/区县目录、作文题快照、作文输入、字数统计、提交、异步批改、完成记录与异常 debug。
- 不新增每日写作、草稿箱、范文库、重写按钮、排行或虚构数据。视觉板中的题名、区县、分数和作文正文仅为布局占位，不进入代码或线上内容。

## 代码事实快照

- 目录页真实入口只来自 `pages/material/index?module=writing`；写作模式不显示 CEFR 听力入口。
- 目录首屏先用 `MATERIAL_HOME_SNAPSHOT_KEY` 或 `store.getCachedReadResult('getMaterialIndex', { moduleId })` 快照，再后台刷新 `store.getMaterialIndex({ moduleId })`。
- 目录层级固定为：`stages` → `exams` → `districts` → `items`；高中当前由 `buildStages` 返回 `0 题` 与空 `exams`。
- 题目点击会写入 `currentWritingPromptV1` 和 `WRITING_PROMPT_SNAPSHOT_KEY`，再跳转到 `pages/writing/detail/index?id={{_id || id}}`。
- 详情页真实字段为：`prompt`、`essayText`、`wordCount`、`editorFocused`、`submitting`、`grading`、`review`、`reviewCelebrating`、`writingDebugLines`、`errorText`。
- 批改结果只渲染现有字段：`score`、`totalScore`、`level`、`summary`、`content`、`structure`、`language`、`spelling`、`problems`、`suggestions`、`grammarCorrections`、`polishedVersion`。

## 模块叙事

写作不是“资料卡列表”，而是从图书馆档案柜取出一份考题，落座编辑桌完成稿件，再收到带校对痕迹的批改报告。目录页使用档案柜、索引签、抽屉编号；详情页使用稿纸、墨迹、段落尺、编辑批注和校对章。两页同属书房，但空间与任务层级明显不同。

## 页面一：写作目录

### 真实路由与数据

- 路由：`/pages/material/index?module=writing`。
- 首屏字段：`title=写作`、`eyebrow=英语写作`、`copy=按学段和模考类型选择作文题。`、`stages`、`count`、`itemUnit=题`。
- 真实层级：学段（初中/高中）→ 模考（二模/一模）→ 区县 → 作文题。
- 进入详情：整行点击写入 `currentWritingPromptV1` 与 `WRITING_PROMPT_SNAPSHOT_KEY` 快照，再导航到 `/pages/writing/detail/index?id=...`。

### 首屏结构

1. 融合式顶部导航：羊皮纸标题带，左侧“英语写作 / 写作”，右侧为一张从黄铜书挡后抽出的稿纸索引；不使用独立大卡。
2. 主场景“作文档案柜”：首层只显示真实学段抽屉。初中抽屉显示真实题数；高中为真实 `0 题`，不伪造可用内容。
3. 选中后原位切换抽屉内部，不纵向叠加多层卡片：抽屉面板依次呈现二模/一模、区县索引签和题目文件夹。

### 层级呈现

- 学段：横向两只宽抽屉，不用圆形编号；黄铜铭牌写“初中 / 高中”，右下角显示“{{count}} 题”。整只抽屉可点。
- 模考：打开的抽屉内呈左右并列文件夹脊“二模 / 一模”，保留真实顺序（二模在前）。
- 区县：字母索引式窄签纵向排列，显示区县与题数；轻微错位表达纸签，不做每项悬浮卡。
- 作文题：文件夹内连续稿件清单，显示 `title` 与 `year · district · examType`，右侧只保留“作文”校对章；整行进入详情，不另放按钮。
- 返回：沿用真实逐级返回语义“‹ 学段 / ‹ 模考 / ‹ 区县”，视觉为页边索引签，点击区域不小于 `44px`。

### 状态

- 加载：遵循现有静默加载规则。无快照时先保留稳定的标题带与两只纸抽屉骨架，标题/副文使用真实 `baseConfig`，不显示“加载中”；有快照立即显示真实目录，后台刷新不重置层级。
- 空：真实学段或模考为空时，在打开的抽屉内放一张空借阅单，文案沿用“暂无内容。”；抽屉仍可返回，不展示虚构题目。
- 正常：当前层级只有一个视觉焦点；滚动只发生在索引或题目清单区域，顶部标题带保持稳定。
- 完成：目录本身无完成字段，不制造完成进度、勾选或最近完成标记。
- 错误：`debugLines.length > 0` 时，在档案柜下沿展开低饱和砖红“馆藏校验单”，完整保留真实 DEBUG 链路文本并支持复制；正常态隐藏。

### 唯一强动作

当前层级整行选择（最终为进入作文题）。不增加“开始写作”按钮。

### 独有图案与控件

- 图案：黄铜抽屉拉手、稿件索引签、校对章、页边编号、短墨迹。
- 控件：整行抽屉、文件夹脊、区县索引签、逐级返回签。
- 动效：点击抽屉下沉 `1px`；层级切换用 `160–220ms` 纸页横移/淡入，不模拟真实开柜的重动画。

## 页面二：作文详情与批改

### 真实路由与状态字段

- 路由：`/pages/writing/detail/index?id={{promptId}}`。
- 题目字段：`examType`、`district`、`title`、`minWords`（默认 60）、`score`（默认 20）、`prompt`。
- 编辑字段：`essayText`、`wordCount`、`editorFocused`、`submitting`。
- 结果字段：`grading`、`review`、`reviewCelebrating`、`errorText`、`writingDebugLines`。
- 报告内容：总分/等级、摘要、内容、结构、语言、拼写标点、可优化处、建议、句子打磨、参考改写。

### 首屏结构

1. “编辑桌标题栏”：`{{examType}} · {{district}}`、真实题名、`不少于 {{minWords}} 词`、`满分 {{score}} 分`，像文件封套题签，不做 Hero 卡。
2. “题目纸”：完整真实 `prompt.prompt` 在可展开羊皮纸上，右上折角、左侧细装订孔；长题干自然换行，不截断。
3. “写作稿纸”：首屏露出纸头、`{{wordCount}} 词` 与至少三行可输入区域，确保进入页面就能理解唯一任务是写作。
4. 主动作“提交批改”位于稿纸末端，墨蓝实心、黄铜细边；页面中不出现第二个同权重动作。

### 编辑交互

- 输入框沿用真实 placeholder：“在这里安静写下你的作文”。横线间距必须等于输入行高；段落尺和页边批注不得遮挡光标或正文。
- `wordCount` 实时更新，仅作计数，不以红色警告少于 `minWords`；现有逻辑允许短于题目建议词数的作文进入模型评分，但少于 20 个字符时提示“先写完整一点再提交。”。
- 聚焦时只加强纸边与黄铜书写灯光，不缩放稿纸，不抬升按钮。
- `submitting=true` 时主按钮保持原尺寸并显示局部 loading；不可重复提交。

### 状态

- 加载：优先显示目录快照中的真实题名/元信息；完整 `prompt` 缺失时后台按需补齐。题目正文区域显示无文字的纸纹骨架，不写“加载中”，稿纸暂不成为可提交状态。
- 空/缺题：`prompt` 最终不存在时保留编辑桌空文件套，显示真实错误文案“作文题加载失败。”；隐藏或禁用提交，避免空题写作。
- 正常未写：题目纸 + 空稿纸 + `0 词`；主动作“提交批改”。
- 正常写作：墨水正文覆盖稿纸线，字数更新；题目纸可在上方阅读，不做悬浮遮挡。
- 输入不足：稿纸下方用低饱和砖红编辑批注显示“先写完整一点再提交。”，不弹大面积红框。
- 已提交/批改中：作文原稿保留可读；主动作进入不可重复提交状态。稿纸下方出现“正在批改”校样夹，文案沿用“作文已保存，稍后会生成批改报告。”；若当前实现同步设置 `errorText=作文已提交，正在批改。`，视觉应降级为提示批注，不作为失败态；可用一条缓慢移动的黄铜校对尺表达处理，不显示伪进度。
- 完成：报告像叠放在原稿后的编辑回函。顶部显示 `{{score}} / {{totalScore}} 分` 与 `level`；摘要先行，下方按“内容 / 结构 / 语言 / 拼写标点”四枚页边索引分块，再显示“可优化处 / 建议 / 句子打磨 / 参考改写”。不把每块做成同款卡片。
- 完成动效：保留首次结果的 `Nice writing.` 与约 1.6 秒庆祝；视觉改为校对章轻落、三点墨迹上浮，禁止礼花和强闪烁。
- 错误：提交或批改失败时显示“批改失败，可以再点一次提交。”，主动作恢复可重试；下方“馆藏校验单”展示 `writingDebugLines` 的真实链路。错误色只用于细边、章印和标题。

### 批改报告结构

- 摘要：独立编辑附言，墨蓝纸条，不使用分数仪表盘。
- 内容/结构/语言/拼写标点：同一张报告纸上的四段编辑栏，由黄铜段落尺和页边索引分隔。
- 可优化处/建议：苔藓绿批注线，使用真实数组逐条呈现。
- 句子打磨：三行固定语义“原句 / 改为 / 原因”，原句用次级墨色，改写用苔藓绿，原因用正文灰。
- 参考改写：报告末尾完整稿纸页，标题沿用“参考改写”；家长查看链路可直接复用此结构，不隐藏题目或范文。

### 唯一强动作

“提交批改”。批改完成后不新增强按钮；返回由系统导航承担。

### 独有图案与控件

- 图案：稿纸横线、墨迹、页边编辑批注、段落尺、校对章、纸张装订孔。
- 控件：大面积原生 `textarea`、稳定字数签、单一主按钮、报告索引签。
- 禁止：圆形进度、分数仪表盘、彩色庆祝点阵、每段反馈一张卡、红色满屏纠错。

## 与雾蓝玻璃的结构差异

| 场景 | 雾蓝玻璃（默认） | 图书馆静谧 |
|---|---|---|
| 目录首屏 | 渐变 Hero + 横向学段卡 | 融合标题带 + 档案柜抽屉 |
| 层级浏览 | 多层 drawer/card 列表 | 单一抽屉原位切换，文件夹与索引签 |
| 题目入口 | 玻璃节目抽屉、圆形波形图标 | 连续稿件清单、校对章 |
| 详情容器 | 雾蓝渐变纸卡与玻璃编辑卡 | 编辑桌上独立题目纸、稿纸、回函 |
| 输入区 | 蓝线信纸、珊瑚主按钮 | 墨蓝稿纸、黄铜焦点、墨蓝主按钮 |
| 批改结果 | 分块玻璃卡与彩色完成点 | 单张编辑报告、页边索引、校对章 |
| 错误 | 雾蓝信息块 | 低饱和砖红馆藏校验单 |

## 实施注意点

1. 只新增 `theme-library` / `pageSkin=writing` 的结构或 token 覆盖；数据请求、快照、提交、批改、完成记录和 debug 文本完全复用。目录不得因主题切换重置当前业务数据。
2. 详情初始 `prompt=null`，当前 WXML 会直接访问字段；实施时必须保证骨架/缺题分支明确，避免空标题闪烁。目录瘦身数据可能没有完整 `prompt`，进入详情仍需沿用按需补齐。
3. `textarea`、按钮、长英文题干与报告数组需在 320–430px 宽度验证：不遮挡、不横向溢出；原生输入层级不得被纸纹伪元素覆盖。debug 仅异常出现，问题修复确认后按线上调试规则撤掉可见信息。

## 视觉板说明

`writing-board.png` 覆盖：目录首屏、区县/题目目录、详情写作态、批改中、完成报告、空/错误状态。板中示例题名、区县、正文、得分只用于评审布局，真实上线内容仍由现有字段渲染。

视觉板必须表现：档案柜抽屉、索引签、稿纸、信笺题目纸、编辑批注、校对章和单张批改回函；不得画成竖条列表、后台表格、分数仪表盘、草稿箱或新增功能入口。
