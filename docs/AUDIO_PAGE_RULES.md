# 音频页统一开发规则

适用：音频导航、级别切换、系列列表、计划设置、课程页、播放器及相关云函数。

## 1. 核心职责

- 音频页只负责“选择听什么”，不做学习数据看板。
- 公共内容、学生计划、学习进度必须分层，不能混成一个接口或缓存。
- 首屏先显示可用内容，计划和进度在后台合并，不能阻塞公共列表。

## 2. 数据边界

### 公共资源

- 级别、系列、任务 ID、顺序、标题、时长、封面、音频地址、分片和 transcript 元数据均为公共资源。
- 公共目录缓存键固定为 `级别 + 系列`，禁止加入学生、家庭、设备身份。
- 切换学生不能重新下载或清空公共目录。

### 学生计划

- 仅包含是否已选、起止范围、每日数量、目标播放遍数。
- 计划状态独立请求、独立缓存，再按 `category` 合并到公共目录。
- 保存或取消计划不得清除公共音频目录缓存。

### 学习进度

- 播放遍数、断点、完成状态、有效收听和打卡按学生隔离。
- 公共列表不得携带学生进度历史。
- 进入课程后再按当前学生补齐进度，不阻塞课程快照首屏。

## 3. 接口与缓存

- 公共系列列表使用轻量接口，只返回展示字段、顶层整集回退地址和首个分片。
- 完整分片、transcript 和学生进度在课程页按单条后台补齐。
- 已有线上正式目录优先生成静态不可变清单，禁止每次进入都扫描云存储。
- 静态清单必须从线上正式文件生成，任务数、ID、顺序、路径和 transcript 关联不得变化。
- 旧完整详情接口和顶层音频字段必须保留，兼容旧客户端。
- 公共缓存采用 stale-while-revalidate；缓存可立即显示，后台刷新不得清空真实旧数据。

## 4. 页面加载

- 无缓存时显示稳定骨架，禁止先显示“共 0 集”再跳成真实数量。
- 音频导航页预取当前级别系列，后台并发上限为 2。
- 用户触摸某系列时优先预取该系列，点击后复用同一在途请求。
- 系列列表显示后不等待学生计划请求。
- 课程已有任务快照时立即渲染并预解析音频；云端详情只能后台补齐。
- transcript、学习包、完整队列等非首播字段按需加载。

## 5. 性能基线

- 公共缓存首屏：`<=200ms`。
- 系列列表冷请求：`<=800ms`，26 个系列每个连续 3 轮均需通过。
- 播放器设置 `src` 到 `onPlay`：最慢值 `<=500ms`，具体音频规格遵循 `docs/AUDIO_UPLOAD_STANDARD.md`。
- 性能报告必须分别记录：级别切换、系列点击到列表、课程快照首屏、点击播放。
- 开发者工具自动化自身固定等待不能冒充应用耗时，报告中必须单独标记。

## 6. 长音频

- 列表只携带首个分片，课程后台补齐全部分片。
- 首片未补齐完整分片前也必须保留原整集地址作为回退。
- 完整分片返回后不得重置已准备播放器、全局时间、断点或文本位置。
- 分片、转码、上传、跨片、拖拽和回退要求全部遵循 `docs/AUDIO_UPLOAD_STANDARD.md`。

## 7. 调试与失败处理

- 调试遵循 `docs/ONLINE_DEBUG_DB_RULES.md`，测试阶段必须输出页面到云函数的断点位置。
- 公共目录失败但有缓存时继续显示缓存，不显示 0 集。
- 计划请求失败不能让公共内容变为不可用。
- 单条音频失败只影响当前条目，不能清空整个系列。
- 修复确认后撤掉临时调试信息，保留性能埋点和正式错误日志。

## 8. 发布验收

1. 验证公共目录与学生身份无关，切换学生后任务数、顺序和地址不变。
2. 验证计划范围、每日数量、播放遍数和断点按学生正确隔离。
3. 使用 CLI + `miniprogram-automator` 覆盖全部 26 个系列，每系列至少 3 轮；长音频另测首条、最长条、随机条及跨片流程。

报告写入 `data/transcript-build/audio-performance`，改动记录追加到 `docs/UI_DESIGN_LANGUAGE_LOG.md`。

## 9. 禁止事项

- 禁止按学生缓存公共音频目录。
- 禁止公共目录接口读取 active plan、历史进度或 transcript 正文。
- 禁止计划请求阻塞系列列表。
- 禁止课程快照首屏等待完整分片或 transcript。
- 禁止通过删除旧路径、旧接口或旧字段换取性能。
- 禁止只测 `audioReady` 后的播放按钮并宣称完整链路已优化。
