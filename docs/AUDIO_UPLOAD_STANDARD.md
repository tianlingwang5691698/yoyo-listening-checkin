# 音频上传与性能规范

适用：听力、课程讲解、口语反馈、词汇发音及所有云端音频。

## 1. 不可变上传

- 上传前读取线上正式清单、云文件状态和本地源文件，不能只看本地报告。
- 已上线可用文件不得覆盖、删除或重命名。
- 新文件必须使用内容指纹路径：`目录/版本/名称-<sha1前10位>-规格.扩展名`。
- 修复缺失文件可以补传到清单已引用但云端不存在的路径。
- 优化版本必须保留旧文件；旧客户端仍能使用原顶层 `audioUrl/audioCloudPath/audioFileId`。

## 2. 编码规格

- 英语听力、课程口播：MP3、单声道、32kHz、CBR 64kbps，移除封面和非必要 metadata。
- 音乐类：确认声道确有必要后使用双声道，码率不得超过 128kbps。
- 禁止直接上传 192/256/320kbps 的纯语音文件。
- 转码后时长与源文件差值不得超过 0.6 秒，正文和 transcript 不得变化。

## 3. 长音频分片

- 冷启动播放器从设置 `src` 到 `onPlay` 的三轮最慢值必须 `<=500ms`。
- 单文件无法达标时首片使用 30 秒，后续使用 90 秒；每片必须为 64kbps mono，首片不得超过 280KB，后续不得超过 800KB。
- 第一片进入课程时预解析；当前片开始后立即下载下一片，片间切换优先使用本地临时文件。
- 分片首播优先获取 CloudBase 临时 COS 地址，公开 CDN 仅作回退；临时地址不能替代分片本身。
- 页面进度、拖拽、断点、逐句文本和有效收听按整集全局时间计算，不能按单片重置。
- 分片清单未完整加载时，越过已加载范围的拖拽不得落到首片本地时间，也不得触发试听、预览或学习完成；必须等待完整清单或回退原整集。
- 分片切换、替换播放器 `src` 或内部停止产生的旧资源结束事件不得视为整集结束。
- 任一分片失败时回退原整集文件；原整集路径永久保留供旧版本使用。

## 4. 增量上传

1. 先运行 dry-run，输出新增、复用、冲突和缺失数量。
2. 只上传云端不存在的新指纹文件；同路径不同内容必须终止。
3. 上传后逐条获取 CloudBase 临时地址并确认可播放；公开 CDN 地址也必须检查。

清单只能增加优化字段或切换到新增的同内容优化路径，不得减少已有系列、任务或 transcript。

## 5. 发布验证

- `ffprobe`：格式、声道、采样率、码率、时长、大小全部达标。
- 音频数、任务数、ID、顺序、时长和 transcript 对应关系不变。
- 微信开发者工具自动化抽测全部系列，每个系列至少一条代表音频，问题系列覆盖首条、最长条和随机条。
- 每条执行三轮冷进入测试，记录 `playTap -> audioPlay`；最慢值超过 500ms 不得发布。
- 必测播放、暂停、跨片、拖拽、断点恢复、倍速、连续播放和完整结束。
- 拖拽必测首片清单补齐竞态、播放中与暂停态跨片定位，并确认不会误触完成流程。
- 上传报告、性能报告和变更记录写入 `data/transcript-build/audio-performance` 与 `docs/UI_DESIGN_LANGUAGE_LOG.md`。

## 6. 禁止事项

- 禁止仅改成临时 COS 地址后宣称完成性能优化。
- 禁止用命令行下载耗时代替小程序播放器耗时。
- 禁止上传后不验证临时地址、公开地址和真实播放。
- 禁止为了提速删除原音频、旧 transcript 或旧版本兼容字段。
