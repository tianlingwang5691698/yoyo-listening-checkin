# 口语练习、录音与评分规则

适用：分级跟读、IELTS Speaking Part 1–3、题目音频、学生记录、家长预览和日报。

## 1. 模式与内容边界

- 口语首页只保留两个同级入口：`分级跟读`、`雅思口语`；两种模式的数据、评分结果和页面状态不得混用。
- 分级跟读固定为 `级别 → 系列 → 音频 → 段落 → 句子`。进入首页不预载全部 transcript；选音频后才加载 transcript，选段落后才渲染句子。
- 音频和段落必须来自该音频的完整正式 transcript，不能每级只放两段示例，不能跨音频借文本，也不能按固定条数截断。
- transcript 分句必须保持原文顺序和标点；没有真实 transcript 的音频标记不可跟读，不用 ASR 幻觉或人工补句填满入口。
- transcript 中的 `Student 1:`、`Teacher:`、人物名等角色前缀只作为独立说话人标记展示，不属于跟读正文；页面和云端评分必须双重剥离，角色词不得计入准确度、完整度或漏读反馈。
- 公共级别、系列、音频、transcript 和题目音频与学生身份分层；切换学生不得重新生成或改写公共内容。

## 2. 分级跟读交互

- 进入段落后自动播放当前句；切换句子后播放新句，点击句子从头重播，不设置重复的“听原句”按钮。
- 播放中的当前句使用轻微浮动和颜色变化；只影响当前句，不让整段或整页变灰，不阻断其他句子点击。
- 点击“结束跟读”后立即提交当前句评分，不再提供独立手动“评分”按钮。
- 评分为句子级后台任务：评分过程中允许切换下一句并继续录音；结果必须按句子 ID 回填，不能覆盖当前已切换句。
- 每句保留独立的评分中、成功、失败和重试状态。成功或失败都保留录音，提供“回放我的录音 / 重新跟读”。
- 返回旧句可以查看旧分数并再次跟读；重新跟读只重置该句当前会话，不清除其他句结果。
- 开始录音时主动停止旧回放不得触发“录音回放失败”；录音中只显示录音状态，旧播放器的延迟错误不得覆盖当前句。
- 原句播放器尚未开始或已自然结束时不得调用无效 `stop()`；只有当前存在有效播放请求时，原句错误回调才允许显示“原句播放失败”。

## 3. 跟读录音与腾讯 SOE

- 小程序录音固定为 MP3、16kHz、单声道、64kbps。
- 正式发音评分固定使用腾讯 SOE 新版 WebSocket：`new / ap-guangzhou / 16k_en`。
- 跟读评分保存总分、准确度、流利度、完整度、原句、录音路径、provider 和时间；返回缺少有效 `pronunciation` 时按失败处理，不伪造分数。
- 上传、评分或云端返回失败时不得清空 `tempFilePath`；必须保留录音供回放和重试。
- 原句播放优先使用可播放 HTTPS 地址；`cloud://` 必须先解析临时地址。公开地址失败时只自动回退一次 CloudBase 临时地址。

## 4. IELTS 题目结构

- IELTS 目录固定为 `IELTS 10–21 → Test → Part 1/2/3`；分册和 Test 目录只存轻量摘要，点击 Test 才加载完整题目。
- Part 1 保留 topic 与逐题 questions。
- Part 2 独立保存主任务、`You should say` cue points 和 closing prompt；念题按当前句逐行高亮浮动，不能让整段题卡一起浮动。
- Part 3 按 discussion topic 分组逐题保存；旧数据粘连多题时保留旧 exerciseId/旧 prompt，新结构用独立 question 复用旧 exerciseId。
- 考试开场进入后自动播放，播放时开场白自身高亮浮动；播放结束点击开场白可重播，不显示单独重播按钮。
- 结构化题目必须能直接完成练习；不依赖“查看原题图片”，历史图片路径仅保留给旧客户端。

## 5. IELTS 评分

- 正式组合固定为腾讯 SOE + `gpt-5.6-sol`：SOE 提供发音与流利度证据，GPT 评估内容、语法、词汇和反馈；禁止静默回退其他模型。
- Part 1、Part 2、Part 3 均按 IELTS Speaking 四项公开标准输出：Fluency and Coherence、Lexical Resource、Grammatical Range and Accuracy、Pronunciation，各占 25%。
- 四项先给整数 Band，总分按 0.5 Band 取整；SOE 缺失时不得伪造 Pronunciation Band，也不得返回看似完整的报告。
- Part 1 按日常问答，Part 2 按长回答与组织，Part 3 按抽象讨论、分析和推测分别评估；不得用同一短回答模板评分三个 Part。
- 页面和记录必须明确标注“AI 练习预估”；不能描述为正式 IELTS 成绩。
- 模型 HTTP 超时固定上限 `240000ms`，重试次数由正式环境配置控制；前端等待期间只锁当前提交操作，不锁整页导航。

## 6. 学生、家长、记录与日报

- 学生模式使用 `planRunType: normal`：评分成功后写入现有 `taskAttempts` 并刷新当日 `dailyReports`。
- 家长模式使用 `planRunType: preview`：允许真实评分和录音回放，但不写 `taskAttempts`、学习进度或日报。
- 云端必须按真实设备学习身份再次强制分流，不能只信任前端传入的 `planRunType`。
- 分级跟读记录按句保存；IELTS 记录按 Test、Part、题目保存，保留模型、provider、四项结果和反馈。
- 学生本人和家长均可查看学生已有口语记录；家长查看为只读，不能重算、覆盖或删除学生结果。

## 7. 缓存与性能

- 口语首页为静态首屏，不请求 IELTS 详情、跟读目录或 transcript。
- 分级跟读只在选择层级后按需加载；IELTS 前两层目录不加载 Part 正文，点 Test 后才加载完整题目。
- 题目 TTS 以文本、音色和生成配置为全局缓存键，成功后使用内容指纹不可变路径供所有用户复用；不按学生重复生成。
- 每个句子评分请求独立关联 requestId/句子 ID；旧请求晚返回不得污染新句状态。

## 8. 发布门禁

1. 内容门禁：级别/系列/音频/段落/句子映射完整，IELTS Part 1–3 顺序、topic、cue points 和 question 数与原卷一致。
2. 音频门禁：录音规格正确，原句和题目音频可播放，公开地址与临时地址回退有效。
3. 评分门禁：跟读有效四项、IELTS 四个 Band、240 秒超时、失败保留录音、逐句并发回填均通过。
4. 身份门禁：学生写记录和日报；家长得到同等评分但数据库写入为 0。
5. 页面门禁：四主题业务状态一致，录音中按钮保持高对比，评分中可切下一句，旧句结果可回看。

验证微信开发者工具时只使用 CLI + `miniprogram-automator` 单会话批量完成，不使用 Computer Use。

### 2026-07-23 分级跟读总分与反馈

- 页面总分固定按 `准确度 × 55% + 流利度 × 25% + 完整度 × 20%` 四舍五入，必须与页面显示的三个分项一致。
- 腾讯 SOE `SuggestedScore` 仅作为 provider 原始审计字段保存，不得直接作为页面总分。
- 每次成功评分必须返回中文反馈；优先指出最低分项的下一步练习方法，三项均达到 90 分时提示重音和语调自然度。
- 回归门禁必须覆盖 `95 / 96 / 100 => 96`，并验证 `SuggestedScore = 66` 不会覆盖统一公式结果。
- 中文反馈固定使用“表现 / 重点 / 下一遍”三行结构；腾讯返回词级结果时必须优先点名漏读、错读和低于 80 分的单词，不得只返回泛化鼓励。
- 词级结果缺失时才按最低分项生成动作建议；反馈生成不得额外调用大模型或增加评分等待时间。
