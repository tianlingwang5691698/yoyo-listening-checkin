# 词汇数据清洗与上传规范

适用：初中、高中、雅思、Unlock 各版本词书，以及词汇释义、音标、例句、例句翻译的新增、补齐、修正和上传。

本规范同时受 `docs/DATA_CLEANING_RULES.md` 和 `docs/CLOUDBASE_SETUP.md` 约束；冲突时采用更严格规则。

## 一、不可突破的边界

- 清洗前必须下载线上正式 JSON，保存带日期的本地备份，并以线上结构为准。
- 线上内容只能增加：不得删除、改名或用本地结果替换已有可用内容。
- 已上线的词条顺序、`word/wordLower`、释义、例句、路径和来源键默认冻结。
- 新数据必须兼容现有云函数、前端和旧版本客户端，不得要求同步改接口才能使用。
- 不得从其他年级、词书、版本、Unit、LS/RW 借词或借释义补缺。
- 原书没有的释义、词性、音标不得凭印象补写；模型生成例句必须明确记录来源并通过审核。

## 二、正式词条结构

### 1. 公共字段

```json
{
  "word": "fantastic",
  "wordLower": "fantastic",
  "phonetic": "/fænˈtæstɪk/",
  "definitions": ["adj. 极好的，奇妙的"],
  "example": "The view from the top was fantastic.",
  "exampleMeaning": "从山顶看到的景色好极了。",
  "source": "source-name"
}
```

- `word`：正式展示词形，去除首尾和重复空格；不得擅自改写连字符、撇号、英美拼写或短语空格。
- `wordLower`：`word` 的小写检索值；只做大小写和空白标准化，不改变词形。
- `phonetic`：使用 `/.../`；不得混入中文、词义、多个无标记音标或 OCR 噪声。
- `definitions`：非空数组；保留词性和原书有效义项，不放例句、记忆法、页眉页脚或解析。
- `example`：完整、自然、符合目标学段，能体现当前义项。
- `exampleMeaning`：与英文例句逐句对应，不增加英文没有的信息。
- `source`：必须可追溯；模型生成内容另加 `exampleSource` 或对应审核记录。

正式新增词条至少必须有 `word`、`wordLower`、非空 `definitions`、所属位置和来源。面向背诵页面发布的最终版本原则上还必须有 `phonetic`、`example`、`exampleMeaning`；确因原始资料缺失而暂缺时，必须进入缺失报告并经任务说明明确放行。

### 2. 初中、高中、四级、雅思 List

必须额外包含：

```json
{
  "level": "junior",
  "list": 1
}
```

- `level` 只能使用既有值：`junior`、`senior`、`cet4`、`ielts`。
- `list` 必须与原书目录一致：初中 1–32，高中 1–40，四级 1–35，雅思 1–48。
- 同一 `level + list + wordLower` 不得重复；跨 List 重复必须能由原书核验，不自动去重到别的 List。

### 3. Unlock 词汇

必须额外包含：

```json
{
  "level": "unlock2-ls",
  "unlockLevel": 2,
  "section": "LS",
  "units": [1],
  "sourceFiles": ["source.pdf"],
  "sourcePage": 4
}
```

- 第二版、第三版必须使用各自现有目录和来源标记，禁止混合。
- `unlockLevel` 只能为 1–4，`units` 只能为 1–8，`section` 只能为 `LS` 或 `RW`。
- 同一版本、Level、Unit、Section 内 `wordLower` 不得重复。
- `sourceFiles/sourcePage` 能从原书核验时必须保留；OCR、人工修正和模型例句分别记录来源。

## 三、清洗规则

1. 先读取线上正式 JSON、对应本地备份、现有构建脚本和同系列正式样本。
2. 从原始 PDF、Word、Excel 或出版社词表提取候选；OCR 结果只能作为候选，不能直接发布。
3. 清除页眉页脚、页码、List 标题、记忆法、搭配提示、二维码、解析和 OCR 乱码。
4. 标准化空白、Unicode、词性标记和字段类型，但不得改变可核验的词形和义项。
5. 按所属词书范围去重；与线上旧词逐条比对，区分 `reuse/add/reject/conflict`。
6. 例句必须检查目标词出现、语法、学段、义项和中英对应；模型生成例句必须保留模型与审核标记。
7. 音标必须检查包裹符号、乱码、空值和词形对应；来源冲突时进入人工审核，不自动选一个覆盖。

以下情况必须拒收：

- 无法确认所属词书、版本、List、Unit 或 LS/RW。
- 缺少单词或有效释义。
- 词形明显为 OCR 拼接、断词或页眉内容。
- 与线上同键内容冲突且无法证明是错误修复。
- 例句不含目标词或其合法变形、中英不对应、语法不完整、难度明显越级。
- 来源不可追溯，或需要修改前端/云函数才能展示。

## 四、清洗产物与报告

每次任务至少保留：

- 原始来源或来源清单。
- 线上上传前备份。
- 最终候选 JSON。
- `clean-report.json`：输入数、通过数、拒收数、重复数、缺失字段数、各 List/Unit 数量。
- `rejected.json`：原始值、位置、拒收原因；不得静默丢弃。
- 例句、翻译、音标由模型或人工补齐时的审核记录。

正式上传前必须满足：

- 全部 JSON 可解析，顶层为数组，字段类型一致。
- 必填字段缺失为 0；重复键为 0；未解释冲突为 0。
- List/Unit/Section 范围合法，文件数量完整。
- 最终总数 `>=` 线上原总数，线上旧词全部仍存在且原顺序不变。
- 单文件小于 1MB；接近上限时必须拆分，不扩大接口返回体。

## 五、线上路径与兼容

- 初高中分 List 正式路径沿用 `dictionary_books/word-lists-examples-v2/<stage>/list-<n>.json`。
- 雅思分 List 路径沿用 `dictionary_books/word-lists-examples-v1/ielts/list-<n>.json`。
- 四级分 List 使用独立不可变 release：`dictionary_books/cet4-v1/cet4/list-<n>.json`。
- Unlock 第二版沿用 `dictionary_books/unlock-v2/level-<n>/unit-<n>/<ls|rw>.json`。
- Unlock 第三版沿用现有 `unlock-v3` 路径；不得写入第二版目录。
- 旧整本词书、旧 release、旧 `sourceId` 必须继续保留，不能因新分 List 数据上线而删除或改名。
- 新结构或同路径存在不同内容时，优先建立新 release 路径；不得复用旧文件名覆盖不同数据。

## 六、增量上传流程

1. 默认只运行 dry-run，输出目标路径、旧数量、新增数量、最终数量、文件字节和哈希。
2. 上传脚本必须先读取线上现状；线上内容与备份不一致时立即停止。
3. 新路径若已存在：内容相同可 `reuse`，内容不同必须 `conflict` 并停止。
4. 既有 JSON 只有在兼容路径确需追加时，才允许上传“旧数组原样 + 新增数组”的加法合并；旧部分必须逐条完全一致。
5. 正式执行必须使用显式 `--apply`；既有路径加法合并还必须有独立确认参数。
6. 上传后重新通过 HTTPS 下载，校验 HTTP 200、JSON、数量、旧数据、追加数据和 SHA256/等价内容。
7. 生成上传报告，记录 `added/reused/conflicts/verified`；任一冲突或验证失败不得继续发布。

禁止直接使用通用上传命令覆盖词书文件。必须使用具备远端检查、拒绝覆盖、加法合并和上传后验证的词汇专用脚本。

## 七、上线验收

- 运行对应词书结构、例句、干扰项、听写和回归测试。
- 抽查首个、中间、最后一个 List/Unit 的词形、音标、释义、例句和翻译。
- 验证旧版本仍能读取旧整本词书，新版本能按 List/Unit 读取。
- 验证词书首页不预加载整本数据，单文件和接口返回不超过 1MB。
- 缓存首屏 `< 300ms`，冷启动云端返回 `< 1200ms`；不达标不得发布。
- 页面验证必须遵循项目要求，使用 CLI + `miniprogram-automator`，不得使用 UI 自动化操作微信开发者工具。

## 八、错误修复例外

只有确认线上旧词存在错误时，才允许修正旧字段：

- 先保存线上原文件和目标词条。
- 单独记录路径、词条键、旧值、新值、证据和影响版本。
- 修复脚本只修改明确列出的字段，禁止顺带重排或格式化全文件。
- 上传前后分别验证旧版和新版读取兼容。
