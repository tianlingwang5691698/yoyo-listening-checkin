# 写作评分专项规则

## IELTS Writing

- Terra 试用期间，写作评分模型固定为 `gpt-5.6-terra`；评分版本必须升级并按模型隔离缓存，旧 Sol 结果不得作为 Terra 测试命中。
- Task 1/2 固定按 Task Achievement/Response、Coherence and Cohesion、Lexical Resource、Grammatical Range and Accuracy 四项 0–9 Band 评分。
- Task 1 与 Task 2 必须分别加载 2023-05 官方公开表的完整 `Band 0–9 × 四项维度` 描述；不得只加载常用高分档或把两个任务的描述混用。
- 官方依据固定为 IELTS 官网的 `ielts-writing-band-descriptors.pdf` 与 `ielts-writing-key-assessment-criteria.pdf`；英文原版为评分权威来源。
- 每个维度必须从 Band 9 开始逐档向下检查，只有当前档全部正向特征均满足时才能给该档；必须同时记录相邻高一档未满足的具体官方特征，禁止凭整体印象、语言流畅度或目标分数给档。
- 所授档位的官方英文描述必须按完整句子生成 `awardedBandFeatureChecks`；每句只能在学生原文直接证明全部要求时标记满足。漏句、部分举证或只证明“没有明显错误”的决策不得作为最终档位。
- `officialBandDecisions` 必须与 `dimensionScores` 一致；决策档位完整有效时以逐档决策为准，程序重新计算四项平均分。
- 模型返回兼容 camelCase、snake_case、官方英文维度名，以及对象或数组形式的逐项反馈。
- 四项 Band 分与 `awardedBandFeatureChecks` 完整时才视为官方评分完成；普通评语、卡分原因或升档动作缺失时保留评分并标记部分反馈。
- 四项 Band 分无法恢复或官方逐档特征证据缺失时校准重试一次；重试仍未完整逐句证明所授档位时返回 `writing-ielts-official-decision-invalid`，不得把裸分作为最终结果。
- Task 1 原图和结构化数据必须同时作为评分依据，不得补造图表数据。
- Task 1 以原图为最终事实来源；模型必须先返回图表事实核对清单，再给四项 Band。`visualData` 只作辅助，不能假设其含有完整曲线数值。
- 四个维度分别只能给 0–9 整数 Band；单项练习分为四项平均后按最近 0.5 Band 报告。
- 作答为 1–20 个英文单词时，四项均按官方描述确定为 Band 1；完全未作答时为 Band 0。
- Task 1 的图表事实核对只提供评分证据，不设置程序自定义封顶；最终档位必须逐条匹配官方 Task Achievement 描述。
- 正式评分调用固定 `temperature=0`；相同评分版本、题目修订和作文正文生成同一 SHA-256 指纹。
- 每项必须引用原文证据，说明为什么完整符合当前官方档位，以及为什么没有完整符合更高一档；不得以目标分数为导向抬分或压分。
- 学生重复提交同题同文时复用其现有 `writingAttempts` 中同评分版本的结果；家长预览使用稳定指纹复用独立 `writingPreviewAttempts`，不得混入学生记录。
- 写作详情页必须按当前学生/家长身份和题目恢复最近一次作文、任务 ID、批改中状态及最终报告；页面退出或重新进入不得清空已提交正文。
- 同一作文进入批改后，提交按钮和编辑器必须锁定；批改完成后正文未修改时仍不得重复提交，只有修改正文后才允许创建新评分任务。
- 云端提交接口必须复用当前评分版本下同题同文的 `grading-pending / grading / grading-failed / graded` 任务，前端失联或重复点击不得新建第二条记录或再次调用模型。
- 家长预览不写 `writingAttempts`、`studyCompletedItems` 或日报；预览任务只允许创建者本人按 `userId + memberId + familyId + childId` 读取。学生提交继续先保存记录，再异步评分。
- 学生在“批改中”返回或退出页面后，已发起的云端评分继续执行并写回原 `writingAttempts`；写作记录必须强制读取最新状态，并自动续查待批改记录，不要求先展开记录。
- 学生评分完成后必须确定性覆盖同日同题 `studyCompletedItems`，并立即重建当日日报；不得让日报长期停留在“批改中”。
- `yoyo` 云函数总超时固定 300 秒；写作提交、评分、历史续批和升档范文客户端等待固定 320 秒。该配置只保证云端有时间完成，不能绕过 `wx.cloud.callFunction` 约 65 秒的资源连接中断。
- 家长预览必须快速创建独立任务，再由评分调用写回；同步连接中断后页面与写作记录自动轮询同一预览任务，禁止重新创建模型调用。
- `getWritingAttemptDetail` 在所有状态下都必须是短时纯读取接口，不得同步调用模型；只有独立 `gradeWritingAttempt` 可对 `grading-pending`、`grading-failed` 或超过 330 秒的真实陈旧任务续批。成功结果必须清除旧 `gradeError`。

## 失败诊断

- 前端错误必须包含页面函数、store action、cloud action、`cloudError.message`、`syncDebug.reason`、`syncDebug.envId` 和 `targetChildId`。
- 不记录作文正文、模型完整返回或密钥；日志只记录错误码和链路字段。

## 回归门禁

- 官方英文维度名可恢复四项 Band 分。
- Task 1、Task 2 的完整官方表均必须包含 Band 0–9，且每个 Band 都包含四项描述。
- 四项逐档决策必须记录从 Band 9 向下检查、当前档全部满足、相邻高一档不满足及具体官方限制项。
- 四项逐档决策必须逐句覆盖所授档位全部官方正向特征，任一特征缺少直接证据时不得覆盖原维度分。
- 逐档决策与普通维度分冲突时，使用已确认“当前档全部满足”的逐档决策档位，并重新计算总分。
- 20 词及以下必须四项归入 Band 1；空作答归入 Band 0。
- 常见证据字段别名可归一为统一结构。
- 四项 Band 分和官方逐档特征证据有效、但普通讲解不完整时必须成功返回。
- 四项 Band 分无效时必须被 `hasUsableIeltsReview` 拒绝。
- 图表事实核对不得机械改写 Task Achievement 分数，评分只能由官方描述匹配决定。
- 四项维度必须归一为整数 Band，平均结果才允许出现 0.5 Band。
- 半分取整边界必须覆盖 `7.125 → 7.0`、`7.25 → 7.5`、`7.75 → 8.0`。
- 同题同文指纹稳定，不同作文指纹不同；评分请求温度必须为 0。
- 新评分校准必须升级评分版本，使旧评分缓存失效。
- 完成记录更新必须使用确定性覆盖写入，评分完成后必须触发当日日报重建。
- 写作记录不得使用过期列表缓存停留在“批改中”；待批改记录进入列表后必须单次触发独立评分动作，并用详情短轮询更新最终分数。
- 回归必须校验 `cloudbaserc.json` 中 `yoyo.timeout=300`，且写作长调用客户端等待为 320000ms；预计超过 60 秒的评分结果还必须先落入可续查记录，禁止仅靠同步返回。
- 家长预览任务 ID 必须指向 `writingPreviewAttempts`，跨用户或跨成员访问必须拒绝；预览评分不得调用学生完成记录写入。
- 正常长批改在 170–330 秒区间不得被轮询重复触发；完成写回后不得残留 `writing-timeout`。
- 记录页和写作详情页的轮询只能调用纯读取详情接口；`gradeWritingAttempt` 对 330 秒内的 `grading` 任务必须立即返回 pending，禁止再次调用模型。
- 任一评分调用失败前必须重新读取原任务；若并发调用已经写入 `graded + review`，必须返回该成功结果，禁止后到的超时或失败覆盖最终状态。
- 回归必须覆盖详情页本地会话恢复、按身份读取最近任务、批改中禁用重复提交，以及云端同题同文任务幂等复用。
